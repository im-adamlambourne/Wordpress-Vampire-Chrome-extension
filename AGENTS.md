# WordPress Vampire

Chrome extension (Manifest V3) that attaches to self-hosted WordPress admin (`/wp-admin/`) so agents can inspect the article editor session and apply title, selected copy, body, excerpt, SEO, Open Graph, and focus keyphrase edits to the open draft (including matching ACF standfirst/SEO text fields). Immediate Media branded (IM cyan-to-royal icon). Target: Gutenberg and Classic. Not WordPress.com Calypso.

## How the extension works

```
Toolbar icon click
 → popup/popup.html
 → chrome.tabs.query (active tab)
 → chrome.tabs.sendMessage { type: 'GET_SESSION' }
 → content/detect.js (injected on *://*/wp-admin/*)
 → session + form field payload in popup Settings (cog)

Editor page (post.php / post-new.php)
  → content/chat-modal.js (isolated world, after detect.js)
  → #wp-vampire-chat host + Shadow DOM
  → floating chat shell
  → snapshot via CustomEvent wpv-editor → content/editor-bridge.js (MAIN world)
  → send → chrome.runtime.sendMessage PLUGIN_CHAT
  → service worker POST {host}/api/plugin/chat (Bearer token)
  → Laravel injects writing_style_guide from a matching assigned site (or the user's only site)
  → reply bubble; if edits, apply via the MAIN-world bridge (Gutenberg wp.data or Classic/TinyMCE)
```

- **Content script** (`content/detect.js`) runs in the isolated world. It probes DOM only (no `window.wp`). On load it sends `SESSION_ATTACHED` so the service worker can paint a per-tab green status light on the toolbar icon. Other tabs stay red (disconnected). `GET_SESSION` returns attach state, editor type, post identity, REST root, and every `input` / `select` / `textarea` in the post form, Gutenberg chrome, and same-origin editor iframes. `detectArticleSnapshot()` is the DOM fallback for chat (title, truncated body, excerpt, SEO/Open Graph text fields, focus keyphrase, editor type). Excerpt/SEO/OG/keyphrase fall back to matching ACF `.acf-field` inputs when the native boxes are empty. Prefer the MAIN-world snapshot when the bridge is ready.
- **Editor bridge** (`content/editor-bridge.js`) is a second content script with `"world": "MAIN"` so it can call `window.wp` and TinyMCE. Isolated overlay code talks to it with `CustomEvent` (`wpv-editor` / `wpv-editor-result`). Snapshot uses `wp.data.select('core/editor')` or TinyMCE/`#content`, plus Yoast (`yoast-seo/editor`) / Rank Math (`rank-math`) stores and matching hidden inputs for SEO title, SEO description, Open Graph title, Open Graph description, and focus keyphrase. When those native boxes are empty it also reads matching Advanced Custom Fields (ACF) text/textarea/WYSIWYG fields (metaboxes via `acf.getField` / `acf/fields` datastore, plus ACF Gutenberg blocks whose slug or field name aliases excerpt, SEO, Open Graph, or keyphrase). It also snapshots the Gutenberg selected block(s) or Classic/TinyMCE highlighted text; a selected ACF block snapshots the block's main text field rather than the raw block JSON. Apply uses `resetEditorBlocks` plus `editPost` for title/excerpt (Gutenberg, so the draft is marked dirty and native Undo still works; `resetBlocks` alone updates the canvas but leaves Save/Update as saved). Selected-copy writes use `replaceBlocks` (Gutenberg) or TinyMCE `selection.setContent` / textarea splice (Classic); a selected ACF block is updated via `updateBlockAttributes` on its text field instead of being replaced with paragraphs. SEO/OG/keyphrase writes go through the plugin store when present, registered post meta, and the hidden inputs (native value setter so React-controlled fields update). The same semantic edits are mirrored into matching ACF fields (`field.val()`, TinyMCE for WYSIWYG, `acf/fields` datastore when enabled) so standfirst/SEO metaboxes update with the native write. Do not pass serialized `content` or a second `blocks` payload into `editPost` after `resetEditorBlocks` — entity subscribers can throw and the overlay then reports failure even though the canvas already updated. Classic uses field/TinyMCE writes with `setDirty`/`isNotDirty` and `input`/`change` (autosave compare and beforeunload). Dirty-marking side effects are best-effort and must not fail a successful write. It never saves or publishes. Incoming HTML has `<script>` tags stripped. Do not add the `scripting` permission for this; the static MAIN-world entry is enough.
- **Chat overlay** (`content/chat-modal.js` + `content/chat-modal.css`) mounts only on Gutenberg/Classic. It injects a Shadow DOM shell (header titled Revision Assistant with the IM circle logo, draft checklist, greeting bubble, composer with labeled glyph quick-actions, collapse/FAB) fixed to the bottom-right. Layout, motion, loader, spinner, and reply sound match the existing chat modal; colour stays Immediate Media cyan/royal (navy header/composer, `#0267c5` user bubbles/send/FAB, sky `#3AB5F4` thinking dots). The opening bubble uses the signed-in first name (`Hi Adam! 👋`) plus the revision-assistant copy, then an **I can also** list for related images and SEO backlinks (same photo/link glyphs as the Livewire chat modal; clicking a row sends that prompt). Robot avatar on agent turns; initials avatar for the signed-in user. While a reply is in flight it shows the `line-loader` thinking dots and a send-button spinner. A new assistant bubble plays `assets/chat-notification.mp3` (volume 0.3). Open/close uses slide+fade motion (`@starting-style` + `allow-discrete`), with a short fade when `prefers-reduced-motion` is set. When signed out, the composer, greeting, checklist, and message list stay hidden; the shell shrinks to a **Sign in** control that starts the same `PLUGIN_LOGIN` identity bounce (the service worker uses the saved host and generates PKCE); if no host is saved it opens the toolbar popup instead. When a plugin token is in `chrome.storage.local`, those chat surfaces return (placeholder **What should change?**). Glyph buttons labeled Images, Backlinks, SEO, and Headlines sit above the field and send those prompts. Send goes through the service worker (`PLUGIN_CHAT`) so the Sanctum token never enters the WordPress page. Laravel injects the signed-in user's site `writing_style_guide` when the wp-admin host matches an assigned site, or when they have exactly one assigned site (local WordPress). After a reply, non-empty `edits` are applied via the MAIN-world bridge; headline ideas arrive as `title_variants` buttons on the bubble. A traffic-light checklist flags missing or over-long title, excerpt, SEO, Open Graph, keyphrase, and thin body — clicking a gap sends a targeted prompt. If the editor has a selection, a hint says the rewrite targets that copy. Transcripts stay in memory for the editor page session. Styles are inlined into the shadow `<style>` (page-origin `fetch()` of `chrome-extension://` is blocked). Keep `CHAT_MODAL_CSS` in sync with `content/chat-modal.css`. Do not add a manifest `content_scripts.css` entry. The robot PNG, notification sound, and IM header logo (`icons/icon-48.png`) are listed in `web_accessible_resources` (`http://*/*` and `https://*/*`; Chrome rejects WAR paths other than `/*`) so `<img>` / `Audio` can load them from the overlay.
- **Popup** (`popup/`) is the sign-in screen. It shows the signed-in user name and either Log in or Log out (never both; the identity bounce still runs in the service worker). After a successful login bounce it reads `loginSuccessMessage` from `chrome.storage.session` and shows **Successfully logged in as {name}** instead of the usual signed-in line. A header cog opens Settings (`<dialog>`) with the configurable Laravel host and WordPress session debug. Keep the popup unless switching to a side panel (which then needs an explicit open trigger).
- **Service worker** (`background/service-worker.js`) is stateless. No globals. Plugin login runs here (`background/plugin-auth.js`) so the identity window can outlive the popup. Overlay **Sign in** sends `PLUGIN_LOGIN` without PKCE; the worker loads the saved host and generates the challenge. If no host is saved it opens the toolbar popup instead. After a successful token exchange it also stores `apiUserName` from `GET /api/plugin/me` so the overlay can draw the user avatar without putting the Sanctum token on the WordPress page, then shows a Chrome notification and reopens the plugin popup (`chrome.action.openPopup`, falling back to a `chrome.windows.create` of `popup/popup.html` because the identity bounce consumes the user gesture). Chat HTTP runs here (`background/plugin-chat.js`) so optional host permissions apply and the token stays out of the content script. Persist host, token, and `apiUserName` in `chrome.storage.local`, PKCE verifiers and the one-shot login success message in `chrome.storage.session`, timers in `chrome.alarms`. Logout and 401 responses clear token and name together. It composites a green/red light onto the IM icon via `OffscreenCanvas` + `chrome.action.setIcon` (the badge API cannot draw a corner light).
- **Permissions**: `tabs` (so `tab.url` is not silently `undefined`), `storage` (host + Sanctum token + display name), `identity` (Laravel OAuth bounce), `notifications` (login-success toast after the identity bounce), `host_permissions` `*://*/wp-admin/*`, `optional_host_permissions` `http://*/*` + `https://*/*` requested at runtime for the configured Laravel origin, and `web_accessible_resources` for `assets/robot.png`, `assets/chat-notification.mp3`, and `icons/icon-48.png` (chat header logo) on `http://*/*` and `https://*/*` (Chrome rejects WAR match paths other than `/*`). Do not add `scripting` until a feature needs it.

## Conventions

- Manifest V3 only. External scripts, `addEventListener`, `async`/`await`, `return true` on async `onMessage` listeners.
- Icons: `icons/icon-16.png` (16×16), `icon-48.png` (48×48), `icon-128.png` (128×128) must exist if referenced. Source mark is the Immediate IM circle (sky `#3AB5F4` → royal `#0B61B6`, white condensed type). Restyle popup UI to that palette; keep `color-scheme: light dark` and `light-dark()` tokens.
- Form debug: redact password/nonce/secret/token values; truncate long values; skip submit/button/reset/image inputs. Batch DOM work with `requestAnimationFrame` and `scheduler.yield()`.
- Popup HTML: semantic landmarks, one `h1`, no inline handlers. Scrollable regions need `tabindex="0"` and an accessible name.

## Load and test

1. `chrome://extensions` → Developer mode → Load unpacked → repo root.
2. Reload the extension after code changes, then reload the WordPress tab so the content scripts reinject (isolated overlay and MAIN-world bridge).
3. Open a post/page editor (`post.php` / `post-new.php`). The **Revision Assistant** chat shell should slide up bottom-right (navy header with the IM circle next to the title, cyan send/FAB). If you are signed out, greeting, checklist, and composer stay hidden and the shell shows **Sign in** to chat about this draft; after login, the full chat, named greeting, and **I can also** list for related images and SEO backlinks appear. The toolbar icon still opens the popup (sign-in on the main view; host and session debug behind the cog).
4. Plugin login: this Sail app is `http://localhost` (port 80; README often says `http://localhost:8080`). Open the popup → cog → Server `http://localhost` → Save host (allow access) → close Settings, then either **Log in** in the popup or **Sign in** in the overlay → sign in (`admin@immediate.co.uk` / `password123` locally) → Connect. A Chrome notification should say you successfully logged in, and the plugin popup should reopen with `Successfully logged in as {name}`. The editor chat composer enables after login. Ask a question about the draft for a `Flash_3_7` reply: the overlay shows the rolling-dot thinking loader, then the reply bubble, a short notification sound, and the user's initials avatar on your turns. Ask to rewrite the title, body, excerpt, SEO, Open Graph, or focus keyphrase; the open editor should update, including matching ACF standfirst/SEO fields when those are the on-screen boxes, Save/Update should show unsaved changes, and Undo in WordPress reverts title/body. Select a Gutenberg block or Classic passage and ask to tighten it — only that copy should change (an ACF block keeps its type and updates the text field). Use the composer glyph actions (Images, Backlinks, SEO, Headlines) and the draft checklist, without saving. Related images and SEO backlinks should insert into the body. Paste an http(s) URL and ask to summarise it or fold it into the draft — OpenRouter fetches the page (the extension does not). Rewrites should follow the matched site writing style guide (or the user's only assigned site when the wp-admin host does not match). The post is not saved or published.
