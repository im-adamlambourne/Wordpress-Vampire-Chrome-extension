# WordPress Vampire

Chrome extension (Manifest V3) that attaches to Immediate Media WordPress Cloud Platform admin (`*.production.wcp.imdserve.com` and `*.release.wcp.imdserve.com` `/wp-admin/`) so agents can inspect the article editor session and apply title, selected copy, body, excerpt, SEO, Open Graph, and focus keyphrase edits to the open draft from the **Content Studio Assistant** overlay (including matching ACF standfirst/SEO text fields). Immediate Media branded (IM cyan-to-royal icon). Target: Gutenberg and Classic. Not WordPress.com Calypso.

## How the extension works

```
Toolbar icon click
 → popup/popup.html
 → chrome.tabs.query (active tab)
 → chrome.tabs.sendMessage { type: 'GET_SESSION' }
 → content/detect.js (injected on Immediate Media WCP `/wp-admin/` and local loopback)
 → session + form field payload in popup Settings (cog)

Editor page (post.php / post-new.php)
  → content/chat-modal.js (isolated world, after detect.js)
  → #wp-vampire-chat host + Shadow DOM
  → floating chat shell
  → snapshot via CustomEvent wpv-editor → content/editor-bridge.js (MAIN world)
  → send → chrome.runtime.sendMessage PLUGIN_CHAT
  → service worker POST {host}/api/plugin/chat (Bearer token) → 202 { request_id }
  → overlay keeps the thinking loader and waits for PLUGIN_CHAT_RESULT
  → Laravel ProcessPluginChatJob on the generative queue; injects writing_style_guide from a matching assigned site (or the user's only site)
  → Reverb PluginChatReplied / PluginChatFailed on private-plugin.{userId}
  → offscreen Echo (wsHost from stored broadcasting.host) → service worker → chrome.tabs.sendMessage PLUGIN_CHAT_RESULT
  → reply bubble; if edits, apply via the MAIN-world bridge (Gutenberg wp.data or Classic/TinyMCE)
```

- **Content script** (`content/detect.js`) runs in the isolated world. It probes DOM only (no `window.wp`). On load it sends `SESSION_ATTACHED` so the service worker can paint a per-tab green status light on the toolbar icon. Other tabs stay red (disconnected). `GET_SESSION` returns attach state, editor type, post identity, REST root, and every `input` / `select` / `textarea` in the post form, Gutenberg chrome, and same-origin editor iframes. `detectArticleSnapshot()` is the DOM fallback for chat (title, truncated body, excerpt, SEO/Open Graph text fields, focus keyphrase, editor type). Excerpt/SEO/OG/keyphrase fall back to matching ACF `.acf-field` inputs when the native boxes are empty. Prefer the MAIN-world snapshot when the bridge is ready.
- **Editor bridge** (`content/editor-bridge.js`) is a second content script with `"world": "MAIN"` so it can call `window.wp` and TinyMCE. Isolated overlay code talks to it with `CustomEvent` (`wpv-editor` / `wpv-editor-result`). Snapshot uses `wp.data.select('core/editor')` or TinyMCE/`#content`, plus Yoast (`yoast-seo/editor`) / Rank Math (`rank-math`) stores and matching hidden inputs for SEO title, SEO description, Open Graph title, Open Graph description, and focus keyphrase. When those native boxes are empty it also reads matching Advanced Custom Fields (ACF) text/textarea/WYSIWYG fields (metaboxes via `acf.getField` / `acf/fields` datastore, plus ACF Gutenberg blocks whose slug or field name aliases excerpt, SEO, Open Graph, or keyphrase). ACF matching runs in three passes over `ACF_MATCH_ORDER` (exact field name, then label, then trailing name segment), most specific semantic first, because Immediate's WCP prefixes its field names (`im-wp-core-description`, `im_seo-meta-title`) and a Radio Times article carries **three** fields labelled "Description" — the standfirst (`im-wp-core-description` → `excerpt`), Open Graph (`opengraph_description`) and SEO meta (`im_seo-meta-description`). A generic label match tried too early claims the wrong one. The keyphrase field there is `im_seo-main-keyword-phrase`. It also snapshots the Gutenberg selected block(s) or Classic/TinyMCE highlighted text; a selected ACF block snapshots the block's main text field rather than the raw block JSON. Apply uses `resetEditorBlocks` plus `editPost` for title/excerpt (Gutenberg, so the draft is marked dirty and native Undo still works; `resetBlocks` alone updates the canvas but leaves Save/Update as saved). Selected-copy writes use `replaceBlocks` (Gutenberg) or TinyMCE `selection.setContent` / textarea splice (Classic); a selected ACF block is updated via `updateBlockAttributes` on its text field instead of being replaced with paragraphs. SEO/OG/keyphrase writes go through the plugin store when present, registered post meta, and the hidden inputs (native value setter so React-controlled fields update). The same semantic edits are mirrored into matching ACF fields (`field.val()`, TinyMCE for WYSIWYG, `acf/fields` datastore when enabled) so standfirst/SEO metaboxes update with the native write. Do not pass serialized `content` or a second `blocks` payload into `editPost` after `resetEditorBlocks` — entity subscribers can throw and the overlay then reports failure even though the canvas already updated. Classic uses field/TinyMCE writes with `setDirty`/`isNotDirty` and `input`/`change` (autosave compare and beforeunload). Dirty-marking side effects are best-effort and must not fail a successful write. It never saves or publishes. Incoming HTML has `<script>` tags stripped. An apply payload may also carry `clear`, an opt-in array of keys to blank so the overlay can undo an accepted suggestion back to a field that was empty before; only `title`, `excerpt`, and the `SEO_FIELDS` keys are clearable, never `content` or `selection`. Do not add the `scripting` permission for this; the static MAIN-world entry is enough.
- **Chat overlay** (`content/chat-modal.js` + `content/chat-modal.css`) mounts only on Gutenberg/Classic. It injects a Shadow DOM shell fixed to the bottom-right: header (IM circle logo, title **Content Studio Assistant**, **Beta** badge, collapse), message list, action bar, idle hint, and the collapse/FAB. Layout, motion, loader, spinner, and reply sound match the existing chat modal; colour stays Immediate Media cyan/royal (navy header/composer, `#0267c5` user bubbles/send/FAB, sky `#3AB5F4` thinking dots) over the translucent glass window (`--window-fill` + `backdrop-filter`). The window sizes to its content between `min-height: 17rem` and the viewport cap.
  - **Action-led, not free chat.** Three flags at the top of `content/chat-modal.js` drive what is on screen: `SHOW_BETA_BADGE` (Beta pill), `SHOW_FREE_CHAT` (composer input + Send; **false** for the beta, and the send path stays wired so flipping it back restores free chat), and `SHOW_DRAFT_CHECKLIST` (**false**; `checklistItems()` is kept). The `ACTIONS` table is the action bar: each entry is `ready` (live button that sends its prompt), `soon` (visible, `aria-disabled` so it stays focusable, SOON pill, click refused) or `hidden` (kept in source with its prompt, not rendered). Today Internal links / Headline / Standfirst / SEO metadata are ready, First sub and Footers are soon, Images is hidden. The active action carries `aria-pressed="true"`; the idle hint (**Choose an action above to get started**) shows until one is picked.
  - **Suggestion cards.** `normaliseReply()` turns a reply into one model whether it carried an explicit `suggestions` array (see the editor-bridge bullet for the shape) or only today’s `edits` / `title_variants`. Field edits (`title`, `excerpt`, `seo_*`, `og_*`, `focus_keyphrase`) become **pending cards instead of being written into the draft**: Accept applies just that field via the MAIN-world bridge and records the previous value, Regenerate re-sends a per-field prompt from `REGENERATE_PROMPTS` and swaps the value in place without adding a bubble — because it is silent in the transcript, the card carries the feedback instead (`REGENERATING_NOTE` in flight, `REGENERATED_NOTE` on success, `REGENERATE_FAILED_NOTE` when the reply did not carry that field, including when it never arrived), Reject dismisses, Undo restores the previous value (blank previous values go through the bridge `clear` list), Reconsider returns a rejected card to pending. `title_variants` become one field card per alternative, so a headline gets the same three buttons as everything else. When several cards share a field their labels are numbered (`Headline 1`, `Headline 2`) so each Accept button keeps its own accessible name, and accepting one returns any previously accepted sibling to pending — inheriting its `previous`, so Undo restores what the draft held before any of them rather than the card just replaced. Internal-link cards are accepted client-side: `insertLinkIntoBody()` wraps the first occurrence of the anchor that sits in body prose — skipping text already inside a link, and anything under `LINK_EXCLUDED_ANCESTORS` (headings, captions, pull quotes, code) — and applies the result as a body edit; `safeLinkHref()` adds a missing scheme and rejects anything that is not http(s). Body and selection rewrites cannot be reviewed field by field, so they still apply as soon as the reply lands. Until Content Studio returns `suggestions`, **Internal links** falls back to `parseLinkSuggestionsFromReply()`, which reads anchors, URLs and titles out of the agent's bullet-list reply, prefers the anchor alternative that is actually linkable in the draft, and strips the parsed bullets from the reply bubble. It only runs for that action, only when the reply carried no structured suggestions, and only when there is no `edits.content` to apply, so it can never fight either. Delete it once the API sends `suggestions`. Cards render as their own full-width `li.wpv-chat__suggestions` row in the message list, not inside the reply bubble.
  - On Classic it also injects an **Add Footers** control into `#wp-content-media-buttons` (next to Add Media / Add Post Element): IM circle logo, cyan-to-royal fill, same height as the WordPress buttons. The host stays in the row but is `hidden` until `ADD_FOOTERS_BUTTON_VISIBLE` is true. A click expands the overlay and sends the add-footers prompt (or starts **Sign in** when signed out).
  - The opening bubble uses the signed-in first name (`Hi Adam! 👋`) plus the action-led welcome copy. Robot avatar on agent turns; initials avatar for the signed-in user. While a reply is in flight it shows the `line-loader` thinking dots (and the send-button spinner when free chat is on). A new assistant bubble plays `assets/chat-notification.mp3` (volume 0.3). Open/close uses slide+fade motion (`@starting-style` + `allow-discrete`), with a short fade when `prefers-reduced-motion` is set.
  - When signed out, the action bar, idle hint, greeting, and message list stay hidden; the shell shrinks to a **Sign in** control that starts the same `PLUGIN_LOGIN` identity bounce (the service worker uses the saved host, or `https://develop.content-studio.im` when none is stored, and generates PKCE); if that origin has not been granted it opens the toolbar popup so **Log in** can request access. When a plugin token is in `chrome.storage.local`, those surfaces return.
  - Send goes through the service worker (`PLUGIN_CHAT`) so the Sanctum token never enters the WordPress page. The overlay treats a 202 `{ accepted, request_id }` as kick-off and waits for `PLUGIN_CHAT_RESULT` (content-script `onMessage`) rather than an inline `reply` on the HTTP response. Laravel injects the signed-in user’s site `writing_style_guide` when the wp-admin host matches an assigned site, or when they have exactly one assigned site (local WordPress). Transcripts stay in memory for the editor page session.
  - Styles are inlined into the shadow `<style>` (page-origin `fetch()` of `chrome-extension://` is blocked). **`content/chat-modal.css` is the source of truth; `CHAT_MODAL_CSS` in `content/chat-modal.js` must be a byte-identical copy.** Do not add a manifest `content_scripts.css` entry. The robot PNG, notification sound, and IM header logo (`icons/icon-48.png`) are listed in `web_accessible_resources` on Immediate Media WCP and local loopback (Chrome rejects WAR paths other than `/*`) so `<img>` / `Audio` can load them from the overlay.
- **Popup** (`popup/`) is the sign-in screen and Workspace launcher. The header shows the signed-in user name and a user icon next to the Settings cog; the user icon opens a **Log out?** confirm dialog (the identity bounce still runs in the service worker). Signed-out popups show **Log in** in the main column instead. After a successful login bounce it reads `loginSuccessMessage` from `chrome.storage.session` and shows **Successfully logged in as {name}** once under the header. When signed in it loads `GET /api/plugin/workspace` (optional `url` of the active http(s) tab) and renders that site's enabled Workspace feature buttons with the hub glyphs (`<x-workflow-icon>` SVG + accent). One assigned site (e.g. Radio Times) shows that site's grid; several sites pre-select the URL match, otherwise Radio Times if assigned, and put the site picker in Settings. Clicking a button opens `/workspace/{siteId}?feature={key}` in a new tab (`chrome.tabs.create`). A header cog opens Settings (`<dialog>`) with the Workspace site `<select>` at the top when the user has more than one assigned site. **Show advanced settings** reveals the Laravel host (default `https://develop.content-studio.im`) and WordPress session debug. The main popup is 800px wide (Chrome’s maximum) with a 6-column feature grid so a full site catalog fits under the 600px height cap. Only Session debug (once advanced is open) is a scroll region. Keep the popup unless switching to a side panel (which then needs an explicit open trigger).
- **Service worker** (`background/service-worker.js`) is stateless. No globals. Plugin login runs here (`background/plugin-auth.js`) so the identity window can outlive the popup. Overlay **Sign in** sends `PLUGIN_LOGIN` without PKCE; the worker loads the saved host (or `https://develop.content-studio.im` when none is stored) and generates the challenge. If that origin has not been granted it opens the toolbar popup so **Log in** can request access. On install it seeds `apiHost` with that default when storage is empty. After a successful token exchange it stores `apiUserName`, `apiUserId`, and public Echo settings (`broadcasting`: `key`, `host`, `port`, `scheme`) from `POST /api/plugin/token` (it does not require `GET /api/plugin/me` when that payload is present) so the overlay can draw the user avatar without putting the Sanctum token on the WordPress page. Echo uses that stored `broadcasting.host` as `wsHost` — the extension does not invent a WebSocket URL for the connection. Laravel derives `localhost:8081` on loopback and `ws.{API request host}` otherwise unless `PLUGIN_REVERB_*` is set. Then it shows a Chrome notification and reopens the plugin popup (`chrome.action.openPopup`, falling back to a `chrome.windows.create` of `popup/popup.html` because the identity bounce consumes the user gesture). Chat HTTP runs here (`background/plugin-chat.js`) so optional host permissions apply and the token stays out of the content script: POST chat includes `telemetry` (OS, browser, and extension version from User-Agent Client Hints, with a `navigator.userAgent` fallback) plus the `action` id of the overlay button that produced the prompt (allow-listed against `PLUGIN_CHAT_ACTIONS`, omitted for free text) so Laravel does not have to infer intent from prompt wording, and returns 202; the worker stores `{ request_id, tabId }` in `chrome.storage.session` and does not wait on HTTP for the reply. Echo cannot live in the service worker (it sleeps after ~30s), so `background/plugin-echo.js` holds Laravel Echo in an offscreen document (`offscreen/offscreen.html`, bundled `offscreen/echo-client.js`) and forwards `PLUGIN_CHAT_RESULT` with `chrome.tabs.sendMessage`. If the Reverb event arrives before the 202 is stored (a fast `generative` worker, or `QUEUE_CONNECTION=sync` running the job before the client maps the tab), the worker buffers it in `chrome.storage.session` and delivers it when the tab id is known. Persist host, token, display name, user id, and public broadcasting config in `chrome.storage.local`, PKCE verifiers, the one-shot login success message, and in-flight chat tab ids in `chrome.storage.session`, timers in `chrome.alarms`. Logout and 401 responses clear token, name, user id, and broadcasting together and disconnect Echo. The toolbar status light uses pre-rendered IM icons with a green or red corner dot (`icons/icon-*-connected.png` / `icon-*-disconnected.png`) via `chrome.action.setIcon` (paths start with `/` because the service worker lives in `background/`; the badge API cannot draw a corner light). Rebuild the Echo bundle with `npm run build:echo` after changing `offscreen/src/echo-client.js` (commit `offscreen/echo-client.js` so unpacked load works without npm).
- **Chat API contract**: request and reply shapes for `POST /api/plugin/chat`, including the `action` id the overlay sends and the `suggestions` array the suggestion cards render, are specified in [`docs/plugin-chat-api.md`](docs/plugin-chat-api.md). Keep that file in step with `background/plugin-chat.js` (request body, `normaliseEdits`, `normaliseTitleVariants`, `normaliseSuggestions`) and `normaliseReply()` in `content/chat-modal.js`. Reply fields are allow-listed twice on the way in — once in `offscreen/src/echo-client.js` where the Reverb payload is unpacked, and again in `deliverPluginChatResult` (`background/plugin-echo.js`) — so **a new reply field has to be added in both places or it never reaches the page**.

- **Permissions**: `tabs` (so `tab.url` is not silently `undefined`), `storage` (host + Sanctum token + display name + user id + public Echo settings from the token), `identity` (Laravel OAuth bounce), `notifications` (login-success toast after the identity bounce), `offscreen` (keep a WebSocket open for chat replies), no required `host_permissions` (a `*://*/wp-admin/*` pattern on that key is treated as all http(s) sites because Chrome ignores the path), WordPress admin attach is `content_scripts.matches` for Immediate Media WCP (`https://*.production.wcp.imdserve.com/wp-admin/*`, `https://*.release.wcp.imdserve.com/wp-admin/*`) plus local loopback, `optional_host_permissions` are the Content Studio origins and matching realtime hosts (`https://content-studio.im/*`, `https://develop.content-studio.im/*`, `https://ws.content-studio.im/*`, `https://ws.develop.content-studio.im/*`, localhost including 8080 and 8081) requested at runtime in one `chrome.permissions.request` (on **Log in** or **Save host**) for the configured Laravel origin **and** a guessed Reverb origin (`http://localhost:8081/*` when the saved host is loopback, otherwise `https://ws.{hostname}/*`) so it matches Laravel’s derived `broadcasting` host, and `web_accessible_resources` for `assets/robot.png`, `assets/chat-notification.mp3`, and `icons/icon-48.png` (chat header logo) on those WCP and loopback hosts (Chrome rejects WAR match paths other than `/*`). Do not add `scripting` until a feature needs it. Do not add `activeTab` for the overlay: it only grants access on an action-icon click, not on editor page load.

## Conventions

- Manifest V3 only. External scripts, `addEventListener`, `async`/`await`, `return true` on async `onMessage` listeners.
- Icons: `icons/icon-16.png` (16×16), `icon-48.png` (48×48), `icon-128.png` (128×128) must exist if referenced, plus matching `icon-{16,32,48,128}-{connected,disconnected}.png` toolbar status lights. Source mark is the Immediate IM circle (sky `#3AB5F4` → royal `#0B61B6`, white condensed type). Restyle popup UI to that palette; keep `color-scheme: light dark` and `light-dark()` tokens.
- Form debug: redact password/nonce/secret/token values; truncate long values; skip submit/button/reset/image inputs. Batch DOM work with `requestAnimationFrame` and `scheduler.yield()`.
- Popup HTML: semantic landmarks, one `h1`, no inline handlers. Scrollable regions need `tabindex="0"` and an accessible name.

## Load and test

1. `chrome://extensions` → Developer mode → Load unpacked → repo root.
2. Reload the extension after code changes, then reload the WordPress tab so the content scripts reinject (isolated overlay and MAIN-world bridge).
3. Open a post/page editor (`post.php` / `post-new.php`) on Immediate Media WCP (`*.production.wcp.imdserve.com` or `*.release.wcp.imdserve.com`) or local loopback. The **Content Studio Assistant** shell should slide up bottom-right: navy header with the IM circle, the title, and a **Beta** pill; named greeting; an action row of **Internal links**, **Headline**, **Standfirst**, **SEO metadata**, plus **First sub** and **Footers** greyed out with SOON pills; and **Choose an action above to get started** beneath. There is no chat input and no draft checklist (`SHOW_FREE_CHAT` and `SHOW_DRAFT_CHECKLIST` are false). If you are signed out, greeting and action row stay hidden and the shell shows **Sign in** to use assistant. On Classic, `#wpv-add-footers` is in the media-button row but hidden (`ADD_FOOTERS_BUTTON_VISIBLE` is false). The toolbar icon still opens the popup (sign-in on the main view; Workspace site, host, and session debug behind the cog).
4. Plugin login: new installs default to `https://develop.content-studio.im`. Open the popup and **Log in** (allow the API origin **and** `https://ws.develop.content-studio.im` when Chrome asks). To use this Sail app instead (`http://localhost` on port 80; README often says `http://localhost:8080`), start Reverb in Sail (`docker compose exec laravel.test php artisan reverb:start`; host port **8081**) and a `generative` worker (`docker compose exec laravel.test php artisan horizon`, or `queue:work --queue=generative`). With `QUEUE_CONNECTION=sync`, chat POST waits on Flash instead of returning 202 immediately. Open the popup → cog → **Show advanced settings** → Server `http://localhost` → Save host (allow the API origin **and** `http://localhost:8081` when Chrome asks) → close Settings, then either **Log in** in the popup or **Sign in** in the overlay → sign in (`admin@immediate.co.uk` / `password123` locally) → Connect. Existing sessions from before 0.6.0 must log in again so the token payload includes user id and Echo settings. A Chrome notification should say you successfully logged in, and the plugin popup should reopen with `Successfully logged in as {name}`. The action row enables after login. Click **SEO metadata** for a `Flash_3_7` reply: the overlay shows the rolling-dot thinking loader, then the reply bubble and a short notification sound, and the suggestions arrive as pending cards — **nothing should be written to the draft yet**. **Accept** one card and only that field should change, including the matching ACF standfirst/SEO field when that is the on-screen box, with Save/Update showing unsaved changes. **Undo** should put the field back, including back to blank (that path uses the bridge `clear` list). **Regenerate** should show *Regenerating…* on that card, then swap the value and show *Regenerated*, without adding a bubble — and show *Nothing new came back* rather than sitting there unchanged if the reply does not carry the field; **Reject** and **Reconsider** must never touch the editor. **Headline** should return one card per alternative — Accept writes the title and marks that card Added, accepting a second should move Added onto it and drop the first back to pending, Undo should restore the original headline rather than the replaced suggestion, and WordPress Undo reverts it. **Standfirst** writes the excerpt / ACF standfirst field on accept. **Internal links** stays on the pre-card path (reply plus a body edit) until Content Studio returns `suggestions`; once it does, accepting a link card should wrap only the first unlinked occurrence of the anchor. **First sub** and **Footers** must not be clickable. The Classic **Add Footers** button stays in the DOM but hidden, and still sends the footers prompt when `ADD_FOOTERS_BUTTON_VISIBLE` is true. Set `SHOW_FREE_CHAT = true` and reload to check the composer and Send still work, including selection rewrites (select a Gutenberg block or Classic passage and ask to tighten it — only that copy should change, and an ACF block keeps its type) and pasting an http(s) URL for OpenRouter to fetch (the extension does not fetch it). Rewrites should follow the matched site writing style guide (or the user's only assigned site when the wp-admin host does not match). The post is not saved or published.

## Out of scope until asked

Save/publish, taxonomies, featured image, Open Graph image, custom meta (other than SEO/Open Graph text fields, focus keyphrase, and matching ACF text fields for those plus excerpt/standfirst), WordPress.com. Public (searchable) Chrome Web Store listing.
